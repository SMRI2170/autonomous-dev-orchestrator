# オペレーターランブック

`ado run` が保存した状態と理由から、オーケストレーターの動作と運用者の対応を確認します。ダッシュボードは読み取り専用で、workerとは独立して動作します。

## QUEUED

- **オーケストレーターが做的事**: 適格なIssueをローカルで予約している。dry-runのスキャンではライブジョブを予約しない。
- **運用者が次にすべきこと**: 通常は待つだけでよい。workerが15秒以上応答しない場合は、後述の対応を確認する。

## BUILDING

- **オーケストレーターが做的事**: 呼出し予算を確保し、許可されたIssueテキストから変更案を生成している。
- **運用者が次にすべきこと**: 変更生成が終わるまで待つだけでよい。モデル呼出し回数とworkerの応答を画面で確認する。

## PUBLISHING

- **オーケストレーターが做的事**: 変更内容とcommit意図を保存し、専用ブランチやPRの作成など公開処理を再開できる状態にある。
- **運用者が次にすべきこと**: 公開処理が進むまで待つだけでよい。処理が進まない場合は、Issue、PRリンク、workerのログを確認する。

## REVIEW

- **オーケストレーターが做的事**: 同一のhead SHAに対するCIと選択したレビュアーの判定を待ち、不合格があれば修正ループを実行する。修正は初回を含めて最大3回である。
- **運用者が次にすべきこと**: CI、レビュー、修正待ちの結果を確認しながら待つ。修正上限、期限、API失敗などに達した場合は`BLOCKED`になるため、停止理由を確認する。

## AWAITING_HUMAN

- **オーケストレーターが做的事**: 判定に合格した変更について、自動マージが無効である場合などに人間を待っている。
- **運用者が次にすべきこと**: PRの差分、CI、レビュー結果を確認し、基準を満たす場合だけGitHub上でマージする。ダッシュボードにはマージ操作がない。マージ後、オーケストレーターがマージとIssue完了を確認する。

## BLOCKED

- **オーケストレーターが做的事**: 失敗、期限、安全基準、上限違反、または依存追加・設定変更により停止している。停止したジョブは自動再試行せず、launchdのプロセス再起動でも再開しない。
- **運用者が次にすべきこと**: 停止理由、状態、workerのログを確認し、下節の対応で原因を解消する。その後も自動再開はしないため、再試行は再実行前に明示的な運用判断として行う。

## DONE

- **オーケストレーターが做的事**: マージを確認し、対象Issueを完了扱いにしている。
- **運用者が次にすべきこと**: 待つ必要はなく、通常は追加対応は不要である。必要なら`ado status`またはダッシュボードで完了だけ確認する。

## BLOCKEDになり得る状況と運用者の対応

- **失敗（API失敗、CLIログイン失敗、モデル呼出し失敗など）**: 停止理由とworkerのログを確認する。`doctor`でCLI互換性を確認し、ログイン、モデル呼出し、契約上限は別途確認して、復旧後に明示的に再試行する。
- **期限超過**: 経過時間と最新のイベントを確認し、期限済み処理を継続させない。原因を解消してから新しい実行操作を行う。
- **安全基準の違反**: 変更パス、内容、機密情報、変更量を検査し、許可されたファイルと内容へ修正する。安全基準は回避せず、修正後に明示的に再試行する。
- **上限到達**: ダッシュボードのモデル呼出し回数と修正回数を確認する。要件を許可範囲内で調整するか、該当する利用枠・上限の制約を解消してから再試行する。
- **依存追加または設定変更**: 保護された依存マニフェストを含む依存追加・設定変更は、このジョブでは続行しない。該当変更を別の作業として扱う。
- **レビューでAPPROVEDが得られない場合**: _BLOCKED_とは自動判定しない。実際のレビュー結果を確認し、自然言語を承認と推測しない。修正不能または修正上限到達によって停止する場合は、停止理由に従って対応する。
- **workerが15秒以上応答しない場合**: ダッシュボードに表示される「応答なし」は、保存された現在地がworkerの稼働を保証しないことを示すだけである。状態、worker、launchdのログを確認する。続いて失敗または期限に達した場合は`BLOCKED`として扱う。

## 無人運転を有効にしない

- `dry_run = true`: Issueの取得、仕様、依存関係を検査するだけで、モデル呼出し、GitHubへの書き込み、ライブジョブの予約は行わない。Keychainの読み取りも行わない。
- `auto_merge = false`: 判定に合格した変更も人間のマージ操作を待つ。

この2つを同時に設定し、「無人運転を有効にしない」構成とする。ライブ運用へ切り替える場合は、セットアップ手順と安全条件を確認したうえで、設定変更を明示的に行う。
