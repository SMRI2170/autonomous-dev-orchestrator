# ADO オペレーターランブック

`ado run`を監視する運用者向けです。`ado dashboard`の「現在地」は最後に保存された工程であり、workerが稼働中であることの証明ではありません。workerは5秒ごとに稼働情報を記録し、15秒以上応答がなければ画面は応答なしと表示します。応答なしという表示だけで`BLOCKED`と判断しないでください。ダッシュボードは読み取り専用で、再試行・マージ・設定変更は既存のCLIまたはGitHubで行います。

## QUEUED

- **オーケストレーターが行っていること:** 適格なIssueをローカルで予約しています。
- **オペレーターの次の一手:** 待つだけで、操作は不要です。予約を取り直したり、別のworkerを手動起動したりしないでください。

## BUILDING

- **オーケストレーターが行っていること:** モデル呼出しの予算を確保し、変更案を生成しています。
- **オペレーターの次の一手:** 待つだけで、操作は不要です。画面では呼出し回数、修正回数、変更ファイル名を確認できますが、状態を操作しないでください。

## PUBLISHING

- **オーケストレーターが行っていること:** 変更内容とcommit意図を保存し、branchやPRへの公開を再開できる状態にあります。
- **オペレーターの次の一手:** 待つだけで、操作は不要です。公開処理を別の手動処理でやり直したり、同じstate_dirで別のworkerを起動したりしないでください。

## REVIEW

- **オーケストレーターが行っていること:** CI、CodeRabbitまたは選択したレビュー、修正ループの完了を待っています。
- **オペレーターの次の一手:** 待つだけで、通常の操作は不要です。必要なら画面に表示されたPRリンクで進捗を確認できますが、自然言語のレビューコメントから正式な承認を推測しないでください。

## AWAITING_HUMAN

- **オーケストレーターが行っていること:** 判定は合格していますが、自動マージが無効であることなどを理由に人間を待っています。
- **オペレーターの次の一手:** 表示されたPRで、現在のhead SHAに対応するCI・レビュー・未解決スレッドを確認します。条件を満たす場合だけ人間の手動でmergeし、その後の実際のmerge確認とIssue完了はworkerに行わせます。自動マージは有効にしないでください。

## BLOCKED

- **オーケストレーターが行っていること:** 失敗、期限、安全基準または上限のいずれかで停止しています。
- **オペレーターの次の一手:** マスク済みの停止理由、最近の工程遷移、変更ファイル、Issue・PRリンクを確認して原因を調査します。DB上の`BLOCKED`ジョブは自動再試行されず、launchdが再起動しても再試行されません。安全条件を弱めたり、原因を確認しないまま再起動したりしないでください。

## DONE

- **オーケストレーターが行っていること:** merge済みを確認し、Issueを完了しています。
- **オペレーターの次の一手:** 待つだけで、このジョブへの操作は不要です。

## BLOCKEDになる場合

状態表では`BLOCKED`を失敗、期限、安全基準、上限による停止と定義しています。文書化された主な状況と対応は次のとおりです。

| 状況 | オペレーターの対応 |
|---|---|
| 失敗、API失敗、レビュー中の処理中断 | 停止理由と最近の遷移を確認し、表示されたIssue・PRと外部サービス側の状態を調査します。出力に失敗内容が混ざらないよう、既存のCLIとマスキング済みの監査情報を確認し、原因がないまま再実行しません。 |
| 期限またはタイムアウト | 記録された理由と時刻を確認し、期限切れの条件を人側で処理します。画面から状態変更や再試行はできず、停止状態の解消と再起動の判断は人側で行います。 |
| 安全基準または仕様・依存条件の違反 | 仕様・依存関係の不備、許可されないパス、内容や秘密情報、変更量、依存追加や設定変更などを確認します。保護条件や安全検査を緩めず、Issueまたは変更要求を許可範囲内で人側から直します。 |
| 上限 | 修正回数、モデル呼出し回数、停止理由を確認します。修正は初回に加えて最大3回で上限に達し、契約上限超過やログイン失敗も停止要因です。カウンタをリセットしたり呼出しを再生したりせず、原因を人側で解決します。 |

`dry-run確認済み`はライブジョブの`BLOCKED`状態ではありません。また、古い工程や15秒以上の応答なしも、保存された状態が`BLOCKED`であること自体は意味しません。

## 無人運転を無効に保つ設定

`docs/launchd.md`に沿って、無人運転を無効に保つ設定・状態は次の二つです。

1. **`dry_run = true`**: Keychain読込み・モデル呼出し・GitHub書込み・ライブジョブの予約を行わない設定です。
2. **ライブLaunchAgentの登録・常駐を無効**: plistを生成しただけでは登録されません。dry-runでの登録・起動確認は、ライブ状態の無人workerを有効にすることを意味しません。

**無人運転は決して有効化しないでください。** 同じ`state_dir`を手動workerとlaunchdで同時に実行しないでください。
